## 二、四项需求实现清单

### 1. AI 分析师（取代程序规则建议）

实现方式：参考 AI4Finance-Foundation/FinGPT、FinRobot 等开源项目的公开做法（LLM 接口 + 实时行情数据），本项目保持轻量，只引入标准 `/chat/completions` 调用，不引入重型训练依赖。

- 入口：[src/ai_analyst.py](src/ai_analyst.py)，默认 DeepSeek `deepseek-chat`，支持任意 OpenAI 兼容接口。
- 输入：当日 A 股指数、重点科技/医药方向、板块、外盘、场内 ETF、近一周/一月走势。
- 输出：基金操作建议、今日基金标的参考、今日观点、风险提示（JSON Schema）。
- 防虚构：基金参考会与真实 ETF 名称/代码核对（`_filter_funds`），伪造标的会被剔除。
- 降级：未配置 Key 或调用失败时自动退回系统规则方案，并在简报中标注实际来源，流程不中断。
- 验证：`tests/test_ai_analyst.py` 覆盖无 Key 快速禁用、JSON 解析、防虚构、AI 优先、规则降级。

已闭环：`AI_ANALYST_API_KEY` 已写入 GitHub Secrets；云端 `--verify-ai` 运行日志确认 `启用: True`、`模型: deepseek-chat（https://api.deepseek.com）`、`就绪: True`，并输出 5 条投资建议、3 条基金参考、今日观点与风险提示，退出码 0。

### 2. 14:05 推送与废弃版本关闭

根因：GitHub Actions 的 `schedule` 定时任务存在排队延迟，实测通常晚 40 分钟左右；且此前远端 `main` 落后于新功能提交，旧代码继续推送。

处置：
- 时间精确化采用“双层时间锁定”：工作流北京时间 13:25 触发（留排队缓冲），脚本等到 13:45 后采集行情，再等到 14:00 整推送微信，送达收窄到 14:00-14:05。相关逻辑见 [src/runner.py](src/runner.py) 与 [.github/workflows/daily_report.yml](../.github/workflows/daily_report.yml)。
- 废弃版本关闭：已核对 GitHub 工作流列表，仓库仅存 1 个活跃「每日股市与基金简报」工作流；远端 `main` 已最新，旧代码不再触发。
- 验证：33 项单测通过；最新 `main` 云端冒烟成功；手动触发不会误带时间锁。

尚未闭环项：今日 13:25 定时任务为真实运行验证点，14:00-14:05 微信送达需实际观测确认（后台任务将于 14:06 自动抓取云端日志）。

### 3. 死循环与大量英文输出的规避

原因复盘：过去对话没有硬性的输出纪律，长任务中反复用英文复述同一意图、整段贴工具输出，造成上下文无谓膨胀与原地打转。

对策：新建 [AGENTS.md](../AGENTS.md) 并同步到全局 `C:\Users\panda\.codex\AGENTS.md`，包含 9 条规则：中文输出、同一句式重复 2 次即中断、先执行后描述、同一阻塞点最多尝试 2 次、复杂任务用计划、长日志截断、不重复贴输出等。

审阅范围：AI 接入、数据采集与备用源、推送链路、时间控制、配置安全、测试覆盖、云端工作流。

审查结论：
